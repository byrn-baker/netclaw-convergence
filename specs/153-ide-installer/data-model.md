# Data model

Normative wire shape: [Claw Plan schema](contracts/claw-plan.schema.json). Protocol 1 / schema 1 use closed objects. Host observation, review authority and verification are not trusted merely because a plan claims them.

## Run state machine

`draft → validated → reviewed → applying → verifying → completed` is the happy path. Every effect starts with a durable `running` intent and ends only after its postcondition is observed. `completed` means the execution has settled; report tiers may still be skipped/unverified and the UI must not label them successful.

During applying/verifying, cancellation or loss of the owning editor produces `pause_requested`. The current bounded owned writer may finish its checkpoint; no new phase starts. Only no active writer plus settled effect evidence permits `paused`. An abrupt process/host death, an unobserved writer or uncertain external effect produces `unknown`; the run retains unresolved ownership evidence. An independent CLI session is not affected by editor loss. Installed services are not setup writers and remain running.

`paused/failed/unknown → observing → resumable` requires explicit Resume, OS locks, exact plan/source/catalog identities, real target ownership and required production controls. The observation result is completed/not_applied/partial/conflict/unknown. Only completed or proven not_applied may advance automatically; a documented owned-partial repair has its own reviewed effects. Conflict/unknown stops. Missing in-memory secrets are re-prompted. Resume never reuses an expired human authorization for changed effects.

## Wizard answers and invalidation

Answers are non-secret, revisioned and persisted only after an explicit setup action. Dependencies: host → prerequisites/source → harness → provider/model/channels → shape/claws → capabilities → settings → inventory/identity/posture → verification/review. A parent change computes the affected descendants and displays a discard preview before acceptance. Preserve unaffected answers. Each member has the same local chain; Border-harness changes update inherited members and preserve explicit overrides subject to compatibility revalidation. Any change invalidates review. Secrets remain in memory outside webview/editor state and are discarded on change/disconnect.

## Existing installation registry

Observe known saved bindings, explicit selected paths and documented default locations without reading credential contents. Record found/unreachable/unknown with detection scope and timestamp; absence from the registry is not proof of absence on disk. Display “Existing NetClaw detected. This setup creates a separate installation.” with manage/select actions. Every operation resolves its saved profile to authenticated installation identity. Per-profile caches, in-flight work and lifecycle/configuration clients are fenced; changing selection cannot retarget an already running operation. Source references and owned endpoint/service reservations are part of conflict checks.

Production policy is engine-owned minimum host/harness/role controls plus requested additions; plan fields cannot weaken it. Verification plan consent fields are choices, not approval credentials. Fixed tiers 1–3 are mandatory. Incomplete drafts retain missing-field diagnostics and are never presented as valid plans.

### Service source and readiness evidence

`services.json` includes `sourceIndex: {sha256,count}` for the private `service-source.json` list of final run-owned relative source paths and digests. Source drift, aliases and path escapes refuse launch and management. Native environment changes do not rewrite source authority. An on-demand member's worker is cold; management services remain hot. A private member health record contains only schema, installation identity, harness, PID, timestamp and readiness; freshness expires after 15 seconds. The Border's authenticated self-status RPC does not wake cold members or invoke a model. Native wake uses the already-reviewed owned unit and waits for channel authentication separately.
