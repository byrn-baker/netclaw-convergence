# Runtime research — R2, R3, R11, R14

Researched **2026-10-17** against this repository, current official documentation, and pinned upstream source. This is research, not installation acceptance. No installed runtime homes, credentials, provider accounts, network devices or external channels were accessed. No runtime command was executed. The only authored artifact is this note; proposed plan corrections below have not silently been applied to `plan.md`.

## R2 — Harness onboarding and discovery

**Decision:** Introduce a versioned harness adapter with explicit capability results, selected-home binding, safe non-interactive configuration, a visible native-interactive fallback, and independent postcondition checks. Do not infer success from CLI exit status or config-file existence. Record the binary/source identity and supported operation set in the run.

The repository's qualified Hermes companion baseline is `v0.21.6`, commit `818c13be1dc4fd28987e1e881a9408224afd4535`, with a file-hash compatibility manifest in `config/hermes-hud-compatibility.json`. Spec149's OpenClaw evidence uses `2026.7.1-2` / `0790d9f`. Those are evidence baselines, not a claim that an arbitrary latest install is compatible. Resolve the desired upstream version separately from the NetClaw source version and qualify or reject it; an upstream version change cannot inherit old protected-companion qualification.

### Repository gaps and rejected alternatives

- `scripts/lib/install-steps.sh:core_onboard` skips onboarding when a config file exists and performs Hermes gateway installation best-effort. This legacy behavior must stay backward compatible, but is insufficient as the new engine's verification contract.
- The legacy Hermes path invokes bare `hermes setup`; the new bridge must explicitly pass the selected `HERMES_HOME` and remove conflicting harness selectors. Do not rely on the shell's active profile.
- Reject duplicating provider enums independently in each front-end. Reject applying arbitrary native wizard defaults that differ from the reviewed plan. If interactive setup changes provider/model/channels or requested posture, reconcile the draft and require fresh review before later effects.
- Reject importing a neighboring runtime's config, provider keys, OAuth sessions or global defaults automatically. New-home selection does not authorize migration or shared credentials.

## R3 — Local providers

**Decision:** Offer version-qualified Ollama and LM Studio detection, plus explicitly configured compatible local endpoints where the selected harness supports them. Keep installed, listening, model available, tool capability advertised, and live turn exercised as separate facts. Listing models must not pull, load or generate. Bind discovery to the user-reviewed endpoint; do not scan the LAN or fall back to a different host.

| Runtime | Discovery and limits | Harness configuration |
| --- | --- | --- |
| Ollama | `GET /api/tags` returns locally available names, digests, sizes and metadata. `POST /api/show` can provide model metadata/capabilities; the existing NetClaw readiness adapter already uses it. Installed bytes do not establish the transfer size of a missing model. [List API](https://docs.ollama.com/api/tags), accessed 2026-10-17; repository `scripts/installer-readiness.py:111–154`. | Current OpenClaw requires the native Ollama endpoint without `/v1`; copying Hermes's OpenAI-compatible endpoint would be wrong. [OpenClaw Ollama guide](https://docs.openclaw.ai/providers/ollama), accessed 2026-10-17. Hermes's documented custom-provider route uses the OpenAI-compatible `/v1` endpoint. [Hermes local Ollama guide](https://hermes-agent.nousresearch.com/docs/guides/local-ollama-setup), accessed 2026-10-17. |
| LM Studio | `lms ls --json` lists downloaded models; detailed listing includes size, architecture and parameter information. Endpoint model visibility and whether a model is loaded are separate checks. [LM Studio CLI](https://lmstudio.ai/docs/cli/local-models/ls), accessed 2026-10-17. | Use the supported LM Studio adapter/configuration for the observed harness version and reviewed endpoint; do not assume every local runtime implements Ollama APIs. [OpenClaw LM Studio guide](https://docs.openclaw.ai/providers/lmstudio), accessed 2026-10-17. |
| vLLM / llama.cpp / other compatible servers | A reachable `/v1/models` response identifies what the endpoint advertises; it does not enumerate all files on disk or prove tool calling. A user-supplied endpoint can remain usable with an explicitly selected model, but model/hardware metadata may be unknown. | Hermes documents custom OpenAI-compatible providers. Record actual provider/API mode and base URL rather than using a generic provider name as evidence. [Hermes providers](https://hermes-agent.nousresearch.com/docs/integrations/providers), accessed 2026-10-17. |

Model selection must record local versus remotely routed models explicitly: a local Ollama daemon can expose cloud model IDs. A loopback URL does not prove offline inference. Display model quantization, context length, available memory and disk with source/unknown states, not an invented universal RAM rule. Model weights, KV cache, tool schema context and concurrency all matter; provider metadata and model-specific guidance bound estimates. The existing readiness code correctly labels supported tools as `advertised_not_exercised`; retain that distinction.

For model downloads, require an upstream model/manifest or catalog size estimate **before** consent. Ollama pull is an effectful operation whose streamed byte counters arrive after it starts, so it is not a read-only size probe. [Pull API](https://docs.ollama.com/api/pull), accessed 2026-10-17. If size cannot be obtained, the UI must say it is unavailable and defer automated download to a visible native workflow with its own size disclosure; never print zero or start a pull merely to discover its size. Task/acceptance coverage must include this failure path.

**Rejected:** treating executable presence as provider readiness; automatically downloading a suggested model; using `/v1` for both harnesses' Ollama routes; treating an installed model's maximum context as the running server's configured context; claiming local inference from an endpoint hostname alone.

## R11 — Single-host, mixed-harness Risks

**Decision:** Preserve the existing NCFED transport/enrollment/runtime adapters and add plan-driven, per-claw materialization with independent identity, config, workspace, credentials, endpoint and service ownership. The plan resolves inherited harness choices explicitly for the Border and every member. The supported capability set is the intersection of catalog, selected harness/version, backend readiness and local execution qualification.

### Existing evidence and limits

- `specs/149-hermes-ncfed-federation/verification.md` proves H/H, H/O, O/H and O/O internal execution on macOS with real pinned harnesses and a deterministic loopback provider. This is substantial reuse evidence, **not** hosted-provider, WSL, arbitrary member-profile or production-control qualification.
- That feature's initial protected execution closure is `subnet-calculator` / `subnet-calc-mcp/subnet_calculator`, IPv4 `/24`–`/30`. `contracts/runtime-execution.md` deliberately freezes that closure. Registered tools do not become qualified merely because discovery succeeds.
- `scripts/in2n-member-home.py:provision_hermes` explicitly accepts only the `subnet` profile. It copies selected Border provider keys; its OpenClaw branch assumes a direct Anthropic provider, embeds its key in config, and symlinks the Border workspace. Those defaults cannot satisfy Spec153's independently chosen member providers and credential/identity isolation unchanged.
- A Hermes Border creating an OpenClaw member currently requires an explicit reviewed OpenClaw template. A mixed OpenClaw Border/Hermes member requires an explicit Hermes model. Do not silently translate arbitrary source config schemas.
- `scripts/in2n-services.py` generates systemd user units, including per-home hash suffixes. It does not generate equivalent launchd Risk services. `scripts/lib/claw-services.mjs` already observes and fences native launchd/systemd services by selected-home environment and executable definition; reuse its ownership checks, not blanket service-name matching.
- `mcp-servers/protocol-mcp/bgp/federation/controls.py:guarded_model_route` explicitly refuses Hermes production model guard qualification. The engine must preserve that refusal and explain it before apply/resume. Spec153 does not authorize pretending those controls exist.

### Required design decisions

1. **Empty-home fence:** Resolve every runtime home and source binding before review. Recheck ownership, symlink/alias collisions, emptiness and port reservations under a run lock before effects. Existing and stopped claws remain existing. Shared immutable reviewed executables may be reused; mutable workspace/config/credential/history state must remain independent.
2. **Explicit credentials:** Build each claw's environment from its own secret-reference set. No copying all Border/provider env entries and no literal provider key in config. Strip inherited cloud/provider variables from child environments; explicit allowed process variables are separate from user secrets. A canary secret belonging to one member must be absent from siblings, Border, process reports and exports.
3. **No implicit borrowed auth:** Hermes profiles use `HERMES_HOME` for application state, while host tool subprocesses retain real OS-user `HOME` by default. Profile state isolation alone is not an external CLI credential boundary. [Hermes profiles](https://hermes-agent.nousresearch.com/docs/user-guide/profiles#how-it-works), accessed 2026-10-17. Disable unsupported ambient auth adoption or refuse the affected configuration; test the actual version's policy. Never run a host-wide gateway migration/update to make a separate installation work.
4. **Service ownership:** Current Hermes gateway behavior includes host/profile multiplexing, so native service installation needs an observed-version ownership policy, explicit selected home, and before/after evidence. A shared gateway cannot silently become a separate installation's manager. Profile aliases and global defaults are not safe management selectors. [Gateway reference](https://hermes-agent.nousresearch.com/docs/reference/cli-commands#hermes-gateway), accessed 2026-10-17. OpenClaw likewise requires isolated state/config/workspaces and ports for multiple gateways. [OpenClaw multiple gateways](https://docs.openclaw.ai/gateway/multiple-gateways), accessed 2026-10-17.
5. **Enrollment secrets:** The engine invokes the existing scoped backend provisioning/enrollment flow after review; raw one-use tokens never travel through assistant tools/events. Keep them in memory or private member-only bootstrap material and remove/revoke them after observed enrollment. Journal only token presence and operation IDs. On an uncertain response, inspect membership and pins before any replacement token or retry. `n2n_member_add`/`n2n_enroll_token` return raw tokens and therefore are not safe direct setup-tool responses.
6. **Hot/on-demand:** Hot members require owned managed processes and routed self-status. On-demand members require enrollment/pinning and an observed usable launch binding, while remaining stopped when idle; their intentional stopped state is not a generic failure. Starting them for verification must be explicit in the reviewed plan and use the same scoped launch path.
7. **Production gate:** Missing, unsupported or unverified controls block before apply/resume for every claw. Retain production intent; only an explicit testing selection and new plan review can proceed. A generic CLI's existing degraded or best-effort behavior cannot bypass this stricter setup gate.
8. **WSL durability:** Check actual PID1/systemd and working `systemctl --user`, not only executable presence. Microsoft documents systemd enablement prerequisites and explicitly says services do not keep a WSL instance alive. Do not promise reboot/session durability outside observed WSL behavior. [Microsoft WSL systemd](https://learn.microsoft.com/en-us/windows/wsl/systemd), accessed 2026-10-17. The native-Windows read-only gate must not enable this or restart WSL.

**Rejected:** treating the four-pair runtime test as broad integration qualification; using member labels as unique installation IDs; one shared provider env file; silently downgrading production; teaching the Border domain tools instead of preserving its routing/audit/memory role; assuming a launchd service supplies Linux confinement.

**Qualification implication:** SC-008 now requires each Border harness with at least three members, both member harnesses and two providers. Add explicit all-four-pair tests with independent same-harness homes and credentials. Use supported member capability closures; unsupported profiles must be disabled with reasons. Extending qualification beyond subnet requires deliberate protected adapter work and new evidence, not a catalog-only change. Real WSL and hosted-provider acceptance remains separate from Mac controlled-provider fixtures.

## R14 — Verification and truthful reports

**Decision:** Retain the specification's six tiers plus Risk, with typed observations and per-claw provenance. Keep report states `verified`, `failed`, `configuration_required`, `skipped`, `unverified`; preserve the richer underlying readiness reasons. Every fact records observed harness/version, installation identity, plan hash, time and sanitized evidence reference. An earlier installation's passing result cannot qualify a new claw.

| Tier | Reuse / required proof | Do not infer |
| --- | --- | --- |
| 1 Installed | Existing installer artifacts/runtime records, native version capability probe, manifest and selected component files. | Config-file presence is not completed onboarding; an exit-0 no-op is not installation success. |
| 2 Discoverable | `scripts/installer-readiness.py` and `config/installer-access.json` through each component's actual access path; require nonempty expected tool discovery. Execute only the selected harmless local canary. | Generic direct MCP reachability is not proof of a harness-native adapter; discovering tools does not call devices. |
| 3 Running | Owned gateway/engine and HUD readiness, selected-home identity, authenticated extension connection and saved-binding review. Use Spec148/152 ownership and adapter contracts. | Open TCP port, daemon process, or a neighboring claw answering at a default port is not this installation running. |
| 4 Thinking | One opt-in bounded synthetic turn through the selected installed harness/provider with operational tools disabled. Prefer the selected HUD runtime adapter, whose typed request/status path already preserves uncertainty. Record actual completion, provider/model and usage when reported. | A provider catalog/key check is not a harness turn; a response body alone is not completed execution; one turn need not mean one billable API call. |
| 5 Channels | Native selected-channel send path only after one approval bound to exact installation, account/channel/recipient and harmless test content. Record delivered/accepted evidence according to the channel's available receipt semantics. | Channel config, token probe or assistant request is not permission to send. Do not auto-repeat after timeout/unknown outcome. |
| 6 Network | Opt-in selected inventory device; access via its registered pyATS MCP and `pyats_run_show_command` with a reviewed platform-appropriate read-only command, such as `show version`. Capture sanitized outcome locally. | Listing devices, discovering pyATS tools or running raw SSH does not satisfy this tier. No configuration commands. |
| Risk | `n2n_risk_status`, `n2n_member_list`, `n2n_member_health`, `n2n_posture`; enrollment/pin observations; routed self-status for every hot member; per-claw posture and qualified capability checks. | A Border being up does not prove all members are enrolled/healthy or production enforced. |

The repository's current readiness script defaults to configuration-only, leaves `agent_turn` and endpoint operations unverified, and performs an OpenClaw Ollama metadata check only when requested. Hermes provider readiness is explicitly unverified. Extend it or wrap typed observations without changing those meanings. Its native OpenClaw probe requires expected tools and rejects historical empty-catalog/exit-0 results; preserve that protection.

The OpenClaw CLI has a single-turn agent interface, but an engine must bind session/model/home and delivery behavior explicitly; `--local` is a different execution route from the running gateway. [Agent CLI](https://docs.openclaw.ai/cli/agent), accessed 2026-10-17. Hermes documents one-shot chat/structured events; the chosen version's terminal result and process exit semantics need fixtures rather than stdout heuristics. [Hermes chat reference](https://hermes-agent.nousresearch.com/docs/reference/cli-commands#hermes-chat), accessed 2026-10-17. The existing private protected Hermes HUD/federation integration remains the qualified operational path; do not replace it with an unrestricted generic CLI solely to obtain a successful canary.

Optional provider credential validation must be disclosed separately if it incurs inference. Combining it with Tier 4 avoids an unnecessary extra billable check. No test messages or live provider/device verification were performed during this research. Qualification records must distinguish deterministic fixtures, real runtime + controlled provider, real hosted provider, live channel, and real device observations.

Default exported reports need structural projection plus recursive redaction of free text, URLs and evidence paths. Private identifiers and all secrets/tokens must not appear indirectly in stderr or exception text. Detailed export review permits private non-secret identifiers only; it never permits credential content. Keep useful symbolic component/member IDs and reason codes so redacted reports remain diagnostic.

## Concrete corrections proposed for the supplied plan

1. Replace any implication that `core_onboard` is a sufficient apply primitive with an explicit harness adapter and postcondition contract. Add a regression fixture for Hermes's guidance-only `--non-interactive` behavior and an upstream capability/version mismatch test.
2. Expand the Claw Plan data model from a singular harness setting to a resolved per-claw installation descriptor: unique identity, new home/workspace, inherited/overridden harness, provider/model/API mode, credential refs, endpoints/ports, service ownership, capability qualification and hot/on-demand role.
3. Revise R11/M6 from simply wrapping `in2n-member-home.py` to safely extending its materialization contract. Remove Anthropic-only assumptions, Border env copying and mutable workspace sharing from the new plan path. Legacy CLI behavior remains a separately regression-tested compatibility path.
4. Add explicit macOS Risk lifecycle service generation/qualification and selected-home Hermes gateway isolation work. Existing systemd-only helpers and profile docs do not establish either.
5. Keep Hermes production unavailable until model guard/confinement are actually qualified. Missing production control tests must refuse before effects and on resume, with no automatic testing fallback. This implements the clarified requirement; it does not waive it.
6. Add version-stamped provider/model/channel discovery with unknown/unavailable states, source provenance and disclosed network refresh. Do not promise a nonexistent Hermes JSON enumeration CLI. Before the runtime exists, catalog metadata supplies documented choices constrained by its version range.
7. Add endpoint-specific local model adapters and missing-download-size handling; the current OpenClaw-only Ollama check is not sufficient for both harnesses, LM Studio or all local models.
8. Update the qualification matrix to explicitly cover both Border harnesses, all four member pairs, at least three members, two providers, inherited/overridden choices, independent same-harness installations and no cross-home secrets/services. Historical spec149 evidence is a baseline only; Linux/WSL and hosted-provider claims require new evidence.
9. Clarify Tier 4 cost wording to one bounded **agent turn**, potentially involving multiple model/auxiliary calls. Tier 2 discovery, Risk self-status and provider metadata checks must not quietly trigger inference. Record unrun live tiers without claiming completion.

Remaining dependencies: R7/R8 must define secret-safe process environments, native-interactive reconciliation and journaled uncertain outcomes; R9 must encode the qualified member/component intersections; R1/R4 must supply WSL/service prerequisites; R12 must prevent raw enrollment/credential results in provisioning tools. The fixture implementation can proceed with these contracts. Real clean-host, WSL, hosted-provider/channel and usability qualification remains environment-dependent and must be reported honestly.

## Implementation research follow-up — 2026-10-17

WSL ownership now reads `GetUnit` and the typed `ExecStartEx` property through fixed, read-only `busctl --user --json=short` commands. The property preserves argument boundaries and execution flags. New definitions use systemd's `:` prefix to disable environment expansion, retaining literal dollar signs; percent specifiers are escaped. The Python engine and editor share 18 contract cases, including foreign object IDs, changed argv/flags, malformed data and whitespace/Unicode paths. Actual WSL manager acceptance remains pending. Sources: [systemd D-Bus interface](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.systemd1.html), [v255 busctl JSON encoding](https://github.com/systemd/systemd/blob/v255/src/busctl/busctl.c), [v255 execution flags](https://github.com/systemd/systemd/blob/v255/src/shared/exec-util.c). These were inspected read-only; no host service was changed.

Webex cannot be enabled merely by exposing a native install prompt. The published `@jimiford/webex` 0.1.3 plugin calls `api.registerHttpHandler`, whereas the selected OpenClaw baseline exposes `registerHttpRoute` and no `registerHttpHandler`. Its install metadata also names `@jimiford/channel-webex`, different from the published package. This is a source compatibility finding, not a live installation result. Keep Webex configuration-required until a compatible, version-bound adapter/plugin is qualified; do not silently install latest, patch third-party code, or auto-register external webhooks. Sources: [plugin entry at 1bc3274](https://github.com/JimiHFord/openclaw-webex/blob/1bc3274f262f946e0929de501d0d40c48bf3ef5a/src/plugin.ts), [package metadata](https://github.com/JimiHFord/openclaw-webex/blob/1bc3274f262f946e0929de501d0d40c48bf3ef5a/package.json), [selected OpenClaw API](https://github.com/openclaw/openclaw/blob/0790d9f/src/plugins/types.ts), [selected registry](https://github.com/openclaw/openclaw/blob/0790d9f/src/plugins/registry.ts).
