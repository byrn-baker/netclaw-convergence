# Native security perimeter contract

Binding is performed only through VS Code native controls. It names an existing runtime home with matching installation.json, product executable and shared security scope. DefenseClaw pins DEFENSECLAW_HOME/DEFENSECLAW_CONFIG; OpenShell pins XDG_CONFIG_HOME plus explicit gateway/workspace/sandbox. Opposing inherited targeting and insecure flags are removed. HOME remains the user's real home. No CLI command string, executable or scope path arrives from webview messages.

Read operations have fixed argv, shell:false, finite timeouts and output bounds. Probe actual help/version and response shape; unsupported versions remain useful read-only views. Show separately configured policy, native-reported runtime status and unverified actual enforcement. Logs are a bounded redacted snapshot with search; no streaming, external export or telemetry sink configuration.

DefenseClaw modern writer: config get asset_policy.tool and guardrail fields in JSON; config set only asset_policy.tool, guardrail.mode and guardrail.block_at with --json and --expect-sha256. Preserve unrelated config and other rules; native schema/managed-device refusal remains authoritative. Readback of the requested key is mandatory. Tool allowed/denied rows carry name, optional configured connector and reason; global scope affects all connectors. No invented MCP/source scoping. An allow can bypass some checks and is always reviewed as a weakening.

OpenShell: read effective full policy and base policy as JSON, explicitly name gateway/workspace/sandbox, refuse editing when effective policy is global or the base-policy capability is absent. Edit only network_policies; keep all non-network base sections unchanged. Guided rule controls and advanced network JSON use the same preview. Expose native endpoint enforcement/access and layer7 allow/deny fields without pretending a general host blacklist exists. Unmatched access remains governed by OpenShell's policy; removing one allow does not prove another rule/provider cannot permit it. Apply a preserved full base policy via policy set --policy <private-file> --wait; read back the base network policy and preserved sections. The CLI lacks a CAS flag: re-read immediately before applying, serialize this client's operations, disclose that an external writer can still race. No claim of atomic cross-process concurrency. Provider-derived/global policy is displayed separately and never rewritten as a base rule.

Every mutation needs a reason, a native target/before-after/effect review and explicit weakening acknowledgment whenever permissions expand or the direction is uncertain. Changed target/config/policy invalidates review. Private baseline and controlled operation state precede execution; locks serialize a shared security target, including across NetClaw profiles. No raw child stdout/stderr in errors or audit. Result is verified only after exact logical readback; timeout, lost identity or missing postcondition is unknown and never auto-replayed. Recovery uses retained native originals and a fresh review, never blind automatic rollback. No lifecycle start/stop/restart, quarantine, scan-triggered changes or whole-perimeter disable.
