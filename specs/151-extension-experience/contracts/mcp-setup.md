# Per-MCP configuration and setup contract

GET `/api/mcp/configuration` returns descriptors, actual .env target, revision and presence-only fields. Explicit aliases connect catalog cards to components. Duplicate catc metadata is reconciled from canonical supported fields. Unknown fields are confidential/requirement unknown. No masked secret prefixes or complete environment objects reach a card.

PUT `/api/mcp/configuration` requires installation header, integrationId, revision, explicit reviewed confirmation and allowlisted replace/clear changes. Keep is omitted. Check revision immediately before synchronous update; retain private baseline and verify actual requested values privately. Return changed keys, isSet and new revision. No implicit register/restart/probe. Shared keys name other affected integrations. Validation uses explicit kinds; do not infer required/optional when unknown.

Extension setup uses a native root/home binding verified against the selected installation.json and API identity. Fixed actions are allowlisted; card input cannot supply argv/env/file paths. Prepare checks actual prerequisites, helper hashes and configuration baselines; review names host/runtime/installation/files/registrations/downloads/interruption/recovery. Execute only after native explicit confirmation and immediate revalidation. Use shell:false fixed argv, safe selected-runtime environment, private bounded evidence and one lock per installation. The canonical registration helper accepts an expected config revision and rechecks it immediately before its write, including managed sidecar state in the prepared baseline. The coordinator serializes owned operations; final comparison also detects intervening external edits (optimistic concurrency, not a cross-process filesystem transaction). Raw child output stays out of UI/audit; only controlled phase/result codes are displayed. Lost results remain unknown, no replay.

Initial direct scope: existing staged pyATS/GAIT installers (prerequisites ready), canonical OpenClaw registration via existing merger, owned federation restart via existing controller. Each enabled action needs isolated real helper verification before release readiness. Existing Hermes conversion with sidecar-only result is guidance/manual merge, not a successful direct registration. Other unqualified installs/restarts are unavailable with a reason. Reviewed command staging is explicit and never presses Enter. Full installer commands disclose their broader effects.

Postconditions distinguish installed, registered, discovery, runtimeLoaded and endpointVerified. File presence or exit zero cannot claim all states. Private bridge excluded. Preserve unrelated config/operator overrides. Setup evidence stores operation state before launch, after each phase and terminal outcome. A host restart displays interrupted state for prior running operations; inspect instead of replaying.
