# Testbed management research

Research date: 2026-10-11. This is planning evidence, not an implementation or a qualification claim. No device, credential store, running service or installation was changed during this research.

## Decision

Keep the extension a client of the selected host-local HUD. Add a bounded document-management contract to the **existing** HUD testbed facility, with shared validation/prepare/commit helpers. Do not add a management daemon, independent extension file writer, new device authority or assistant mutation tool. Existing extension-only behavior remains the fallback on an older HUD: show inventory and explain that safe editing is unavailable; never fall back to its unsafe raw writer.

The Spec150 boundary was strictly client-only (`specs/150-vscode-extension/contracts/existing-interfaces.md:3`). Spec151 explicitly adds inventory writes and permits necessary bounded support changes (`specs/151-extension-experience/spec.md:10`). A documented, testbed-only supporting-service exception is necessary: the existing server owns active terminal sessions, cached logins and collector grants, which an extension-local YAML writer cannot reliably revoke. This is a narrower change than copying those responsibilities into the extension.

The pyATS schema includes credentials with inheritance, multiple connections, custom fields, topology interfaces/links, encoded passwords and prompt markers. Therefore a successful plain YAML parse is not proof of a usable pyATS testbed. The documentation also permits `extends` and custom classes; import validation must remain inert and must not invoke those loaders or follow external references. [Official pyATS schema](https://devnet-pubhub-site.s3.amazonaws.com/media/pyats/docs/topology/schema.html), [official topology creation documentation](https://devnet-pubhub-site.s3.amazonaws.com/media/pyats/docs/topology/creation.html).

## Proposed document contracts

Names below are a concrete minimal contract proposal for plan integration; they are not existing endpoints.

1. `GET /api/testbed/document`: JSON envelope with `schemaVersion`, `installationId`, `runtime`, server-selected `targetId`, operator-readable `source`, `revision`, `writable`, `devices`, masked editable `content`, and explicit validation/capability information. Cards use an allowlist of ID, alias, type, OS, platform and connection endpoint/protocol metadata. Do not return resolved credentials or arbitrary custom objects to cards. `targetId` binds the fixed server path; callers cannot submit paths.
2. `POST /api/testbed/preview`: read-only preparation over `{targetId, revision, operation}`. Operations are fixed variants: create, update, remove, YAML edit, or import with format/mode/conflict decisions. Return controlled validation errors with location, added/changed/removed IDs, changed field paths, collector revocations and a candidate digest. No device access, file write or revocation occurs while previewing.
3. `PUT /api/testbed/document`: the same exact operation plus revision, reviewed candidate digest and explicit commit intent. Re-prepare server-side; reject if target, revision, candidate or scope changed. Block active terminal sessions for affected devices; durably revoke affected grants and clear cached logins; write private backup; write atomically; read back and verify expected revision; broadcast the existing `config:updated` event. Return revision and opaque recovery ID, not secrets or the full backup. A failed save may have revoked consent; report that explicitly without silently reauthorizing.
4. Export can be a read-only `POST /api/testbed/export` selecting `{targetId, revision, format, credentials}`. Return content only to the extension host. The host obtains a native save destination and explicit credential handling choice, writes once, then discards content. A redacted copy and an exact private backup are different choices. A full YAML backup retains the source bytes; JSON is semantic equivalence for the supported data model, not comment/anchor fidelity; CSV is explicitly a limited inventory view.
5. Recovery can reuse the same preview/commit pipeline with an opaque server backup ID. Server resolves IDs only within its fixed private backup store. Restoration is a fresh reviewed mutation against the current revision and obeys the same session/revocation checks. Never accept arbitrary restore paths.

For minimal implementation, preview need not create a durable server-side session: recomputing a deterministic candidate plus digest against the same revision avoids a new authority store. Reuse existing synchronous file guards and add one commit lock per testbed destination for concurrent requests. Revision checking must happen again after acquiring the lock and before the atomic write. External editors that ignore this process lock still require the final source comparison; document that the mechanism is optimistic concurrency, not a cross-process filesystem transaction.

The new document service should be a narrowly mounted module using injected `file`, selected installation identity, active-terminal predicate, collector revocation and login-forget callbacks. No generic route, shell, arbitrary filesystem selector, device command or privilege expansion is required. A shared helper can subsequently strengthen the legacy raw route without changing its GET/PUT response contract; do not create a new bypass in the extension if the strict capability is unavailable.

## Data preservation and validation

- Use canonical device keys, never `/api/graph` slug IDs. Guided editing covers stable ID on create, alias/type/OS/platform and an explicitly selected connection's protocol/address/port. ID changes are advanced document edits and are reviewed as remove/add; do not silently retarget existing grants.
- Forms can edit common fields on explicit device/connection mappings. A non-SSH transport is valid inventory and must not be presented as invalid merely because the Terminal feature cannot use it. Preserve additional connections, credentials, interfaces, topology, defaults and custom fields.
- Use the existing `yaml` CST dependency for guided and CSV patches. Validate the resulting semantic model against the expected model with only intended paths changed. Shared aliases/merge structures that would change unrelated devices must refuse the form transformation with an actionable YAML-editor alternative. Existing comments and newline style remain intact where untouched.
- Parse YAML/JSON as data only, with a bounded size, nesting depth and alias expansion budget; reject duplicate mappings, custom YAML tags, non-string device keys, nonmapping `devices` and unsafe property keys. Preserve recognized pyATS marker strings without evaluation. Do not instantiate classes, invoke Python loaders, resolve `%ENV{}`, follow `extends`, open a URL or prompt for a credential.
- Distinguish syntax/structural validation from actual runtime compatibility. Unknown advanced fields remain preserved rather than stripped. For unsupported transformations, explain the precise limitation without including source snippets.
- Full replacement preview explicitly includes removed devices and top-level changes. Merge is device-wise and preserves destination top-level data unless separately reviewed; reject ambiguous top-level merge changes rather than silently discarding imported data. Duplicate device choices must be resolved explicitly (skip or replace/merge as defined), not last-row-wins.
- Removing an entry with related `topology[id]` or shared alias references must be explicit. Preview any matching topology section removal; reject transformations that would leave unresolved YAML aliases or accidentally remove another device's data.
- Compute affected devices from semantic before/after records plus shared defaults/credential changes. A change to global credentials/defaults potentially affects every device, so revoke those grants and clear logins. A pure comment change does not invent a network effect. No mutation starts a collector or device session.

## Secret handling

Existing `scrub()` (`extensions/netclaw-vscode/src/client/hud.ts:38`) is a generic display filter, not a lossless testbed masking codec. It misses whole credential maps, `passphrase`, legacy `passwords.enable` and potentially unknown credential field names. Do not use its `[redacted]` output as editable source.

Use a server-generated masked YAML projection with opaque keep tokens bound to the baseline revision and original scalar paths. Preserve `%ENV{NAME}` references as references; encoded credential payloads are secret material rather than safe display text. Cover credential/password containers, passphrases/private-key fields and credential-bearing server/connection objects. On save, restore keep tokens only at their original paths from the unchanged baseline; reject forged, moved or unresolved tokens. A removed secret path must appear as an explicit removal in the review. CST alias handling must either mask the shared scalar consistently or reject an unsafe transform, never leak the anchor's literal elsewhere.

The advanced editor is a sensitive surface. Any user-provided new literal credential remains only in the draft until commit; never persist it through webview `setState`, extension global/workspace state, output channels, diagnostic exports or screenshots. Reviews show field names and secret change intent, not values. Ordinary cards use an allowlist instead of trying to guess which arbitrary custom fields are secrets. Clear draft contents on disposal/invalidation and guard save/discard/cancel transitions between modes. General arbitrary user prose cannot be classified perfectly; avoid exposing unrecognized custom objects in ordinary display.

Import reads files on the extension host using VS Code URI APIs, with file size checks before loading. Redact summaries and validation messages. Explicit full-credential export requires a clear native review showing target source, output destination and private-material warning; otherwise export a copy whose redaction is labeled, not misleadingly called a complete backup. Do not write a temp export into the repository.

## CSV contract

Use a documented fixed subset: `id,alias,type,os,platform,connection,protocol,host,port`. `id` is mandatory; a named connection is mandatory when modifying connection fields. Default SSH/22 is only for an explicitly created SSH entry. Existing rows patch only supplied columns; omitted columns leave existing fields untouched. Define blank values separately: empty optional metadata may clear it; blank required ID/host/protocol or invalid port is an error, never an implicit delete. CSV never deletes unseen devices or replaces an entire existing testbed.

Support UTF-8 with optional BOM, CRLF/LF, quoted delimiters/newlines and escaped quotes. Reject duplicate/unknown headers, duplicate IDs and malformed row shapes with row/column errors. Formula-like values are inert text on import. Export must neutralize spreadsheet formula-leading values and explain that spreadsheet-safe CSV may alter their textual representation; YAML/JSON is the lossless alternative. No credential columns are accepted. A CSV export must describe advanced fields omitted and identify devices/connections it cannot flatten without ambiguity.

## Essential verification

Use temporary HUD/installations and synthetic testbeds only. Cover real HTTP identity/access checks and actual source helpers, then extension-host draft/review binding and webview interaction:

- Valid create/update/delete, YAML edit, YAML/JSON/CSV import/export and empty inventory; known malformed source must remain an explicit error.
- Every supplied CSV shape; full YAML/JSON round trips; equivalent JSON type limits; preserved comments/anchors/defaults/custom fields and multiple connections; duplicate keys and alias bombs rejected.
- Preview makes no write, consent or device connection; cancel makes no write; forms/YAML mode switching retains draft or requires explicit decision.
- Two stale clients, source changed during review, target/installation changed, permission failure, backup failure, atomic-write failure and timeout after commit. Readback establishes current state; no automatic replay.
- Old grant and login removed before an endpoint change; global default/credential change affects all eligible grants; unrelated grants retained; active terminal prevents affected mutation; revocation failure prevents file mutation; save failure reports consent side effect.
- Existing inline passwords, `%ENV` references, encoded passwords, shared credentials, legacy enable passwords and key/passphrase fields never appear in cards/reviews/logs/errors; keep tokens cannot be forged or transplanted.
- Old HUD without document capability is a clear unavailable-editing state. Hermes capability/read-only limitations remain explicit until these inventory-only operations are separately qualified; do not interpret `capabilities.writes` as blanket device authority.

The plan should record these two source limitations explicitly: the HUD file can differ from `PYATS_TESTBED_PATH`, and multiple selected installations can share the same file. Neither should be hidden by the new visual treatment.

## Design resolution after cross-artifact analysis

The final contract in contracts/testbed.md supersedes the proposed duplicate-ID CSV rule: rows are unique by (id,connection), and conflicting repeated device metadata is rejected. Masked source/message size limits are explicit there.
