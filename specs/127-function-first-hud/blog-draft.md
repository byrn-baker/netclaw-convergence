# NetClaw's HUD: start with the work

Local draft for review. Not published. Required browser/live-host acceptance remains pending.

The next NetClaw HUD begins with the operator's work: inspect availability, choose an
investigation, follow the evidence and continue the conversation. Basic and Advanced
change how much detail appears, while authority and change-management rules stay the same.

Adam Mason's branching canvas remains the investigation workspace. Its existing
sessions, source/context/summary/action views, attachments, branches and synthesis
are preserved. A dashboard finding can be added to a draft with its source and time;
that action does not submit a request or execute a tool.

Jev becomes inspectable as an advisor. Its exact dynamic questions and typed judgments
are separate from Border's own interpretation. A rubric position is not network
health, and model agreement is not proof. Detailed records require an authenticated,
server-owned task association established from actual gateway tool-result events.
The global advisor card still carries only safe status. Missing provenance says unbound.

Three.js remains useful for membership, federation and BGP relationships. It is
optional, uses the same entity identities as the tables, and does not pretend that
federation edges are physical cables. Native mobile devices and external neighbours
have distinct views and authority labels.

The implementation includes regressions for saved canvas data, session boundaries,
authorization, typed answers and a real read-only MCP process. The current development
session cannot start local listeners, and browser control was rejected by automatic
approval review. Those acceptance gaps remain explicit. We will not call the HUD
fully verified until the actual browser and deployed runtime journeys pass.
