# Workspace management research — Spec 152

Read-only source inspection, 2026-10-15. No owner workspace contents, credentials or live services were changed. This note records implementation decisions and qualification boundaries rather than declaring acceptance complete.

## Authoritative destinations

- OpenClaw files belong to the selected **agent's configured workspace**, not necessarily `<runtime-home>/workspace`. The installed OpenClaw 2026.7.1-2 resolver prioritizes the agent entry's `workspace`, then the default agent's `agents.defaults.workspace`, then the native default. Non-default agents have different fallback rules. Source: installed `dist/agent-scope-config-BxAUeF6t.js:119–131`. NetClaw already chooses the active agent through `ui/netclaw-visual/src/hud-server/gateway-agent.js:1–10`; ambiguity is an error, and `HUD_AGENT_ID` can override the choice. Its settings projection at `runtime-settings.js:23–29` exposes configured workspace but does not resolve all native fallback rules.
- Hermes persona files are deployed directly into the selected `HERMES_HOME`: `scripts/lib/common.sh:90–96` sets `RUNTIME_WORKSPACE="$RUNTIME_HOME"`; `scripts/lib/install-steps.sh:2739–2748` bootstraps the six files there and preserves existing files. **Do not use the generic `workspacePath` returned by `scripts/runtime-selection.mjs:69` for Hermes**; that currently says `<home>/workspace` for both runtimes and contradicts the installer.
- Installation identity lives in `<home>/netclaw-hud/installation.json`. Existing resolution validates owner, regular files, no symlinks and private modes (`scripts/runtime-selection.mjs:24–69`). Existing extension setup binds the expected installation ID to an explicitly selected host-local home (`extensions/netclaw-vscode/src/client/setup.ts:55–69`). The current `/api/runtime` client type carries identity/kind but no host-local home/config/workspace binding (`src/client/hud.ts:4–10`); a management binding must be introduced and revalidated rather than guessed from repository location or ambient environment.
- Preserve explicit `OPENCLAW_CONFIG_PATH` and selected agent identity. `setupEnvironment` currently hard-codes `<home>/openclaw.json` (`setup.ts:95–99`); that shortcut is unsuitable for workspace management on installations using a custom config path. Resolve includes/native JSON5 configuration through a reviewed native query or existing authoritative server projection, not a new partial JSON parser silently ignoring configuration semantics.
- Persist only the validated binding metadata needed for offline management. Revalidate home identity, config revision, selected agent, workspace directory identity and host context before every write. A stopped HUD must not erase the saved selection.

### Native OpenClaw discovery follow-up

Prefer **`openclaw agents list --json` without `--bindings`**, invoked as an argv array using the selected installation's actual launch environment, CWD, executable and custom `OPENCLAW_CONFIG_PATH`. The installed CLI registers that command in `dist/register.agent-DjqV6VBR.js:46–52`; `agents.commands.list-m4wiNATp.js:249–285` reads validated config and emits summaries. `agents.config-B4WInwf4.js:35–52` directly calls the native `resolveAgentWorkspaceDir` and returns `id`, `workspace`, `agentDir` and `isDefault`. It also reads identity name/emoji, so retain raw subprocess output privately and immediately project only required binding fields. Omitting `--bindings` avoids provider-account detail inspection (`agents.commands.list-m4wiNATp.js:264–266`). This discovers metadata without copying hashed bundle imports into extension code.

`openclaw config get agents --json` is also registered (`config-cli-DlbmNqwQ.js:1746–1750`) and selects a redacted config subtree (`1566–1588`), but does **not** itself resolve workspace paths. Both queries use `readConfigFileSnapshot` with native JSON5/include/env processing. Native snapshot reads may update config-health fingerprints/audit metadata (`io-By0s-a_s.js:4786–4820`); they are not a guarantee of zero filesystem side effects. They do not request a config mutation or suspicious-config recovery.

Exact installed fallback: `resolveAgentWorkspaceDir` (`agent-scope-config-BxAUeF6t.js:119–131`) prefers per-agent workspace; for the default agent, uses defaults.workspace or `resolveDefaultAgentWorkspaceDir`; for other agents, uses `path.join(resolvedDefaultsWorkspace,id)` or `path.join(resolveStateDir(env), 'workspace-'+id)`. `workspace-default-ClCi3unQ.js:12–18` prefers `OPENCLAW_WORKSPACE_DIR`, otherwise builds `<effective-home>/.openclaw/workspace[-<profile>]`. **Native `OPENCLAW_HOME` means effective user home, not the state directory** (`home-dir-CJKEsOtx.js:34–56`). `OPENCLAW_STATE_DIR` independently sets state (`paths-BMBAvkNf.js:46–62`). Consequently setting `OPENCLAW_HOME=<selected-state-home>` can produce `<selected-state-home>/.openclaw/workspace`; copying NetClaw's generic environment builder would change native defaults. Resolve against actual launch metadata instead of fabricating environment values.

## Runtime consumption is not symmetric

- OpenClaw's installed `dist/workspace-DkQ7irPD.js:740–795` loads all six requested catalog files as bootstrap candidates. Its session filter at `797–809` limits subagents to AGENTS/TOOLS and cron sessions to AGENTS/TOOLS/SOUL/IDENTITY/USER. Therefore “every session” is too broad even for OpenClaw. A save is disk persistence; a successful restart does not prove an existing conversation consumed that revision. Heartbeat content is meaningful only for configured heartbeat execution.
- Qualified upstream Hermes v0.21.6 (`818c13be1dc4fd28987e1e881a9408224afd4535`) reads SOUL from the active profile home. Project instructions are discovered from session working directory, with `.hermes.md/HERMES.md` taking precedence over an AGENTS chain, followed by CLAUDE and Cursor rules. AGENTS at the profile home is therefore conditional on working directory and higher-priority files. USER/TOOLS/IDENTITY/HEARTBEAT are not established as equivalent automatic bootstrap inputs. Sources: [pinned prompt builder](https://github.com/NousResearch/hermes-agent/blob/818c13be1dc4fd28987e1e881a9408224afd4535/agent/prompt_builder.py#L1648), [context-source enumeration](https://github.com/NousResearch/hermes-agent/blob/818c13be1dc4fd28987e1e881a9408224afd4535/agent/context_file_sources.py#L51).
- **NetClaw's protected Hermes HUD/federation companion intentionally consumes none of those ordinary owner files.** `mcp-servers/hermes-hud-mcp/protected_agent.py:16–21` sets `skip_context_files=True` and `load_soul_identity=False`; `hermes_api.py:32,61–67` uses a generated private shadow profile and CWD. Keep that isolation. The UI should identify owner persona storage separately and say that protected companion instruction loading is disabled. Restart must not claim to activate those files in the protected companion. Changing that policy is outside this workspace-editor feature.

## Reusable interfaces and needed strengthening

- Connection authority: `src/connection/connect.ts:23–63` enforces Workspace Trust, host context, installed identity and runtime kind. `bound():69–88` uses a generation and client reference to reject late/stale operations. Retain equivalent **selection** generation checks for management, but do not require a live HUD for Start or offline status. Current `disconnect():100–107` clears profile and identity, so it is not an offline management model.
- UI placement: the `NavigationTree` in `src/views/overview.ts:9–33` maps entries to commands; add the file catalog and lifecycle commands in the upper Connections tree. `src/views/testbed.ts:130–162` demonstrates preview token, native modal target review, identity recheck and explicit save. Upload is picked on the extension host (`174–187`); filenames must remain display metadata, never destination paths.
- Draft handling: `src/views/testbed.ts:106–128` supplies keep/discard/cancel behavior. `src/webview/panel.ts:24–29` retains selected editing views when hidden, but currently requires `connection.bound()` and invalidates on disconnect. A management editor needs an offline-capable selection binding. Existing webview message limits (`72–77`) are **300,000 characters** for ordinary views, and the data bridge caps serialized output at 1 MiB (`bridge.ts:56`); neither directly supports a full 1 MiB UTF-8 Markdown draft plus JSON overhead. Validate content bytes separately from an adequately bounded transport envelope.
- Local state: `src/state/local.ts` uses private local extension storage and atomic writes, avoiding Settings Sync. Store binding/evidence metadata there, not file contents. Private recovery copies should live under the selected installation's private management state, outside source control and readable after HUD Stop.
- Existing atomic file helper (`ui/netclaw-visual/src/security/private-files.js:6–33`) checks a final regular-file target, writes an exclusive private temporary, fsyncs and renames. Testbed saves (`testbed-document.js:577–628`) add digest review, immediate stale check, original recovery and readback verification. These are useful patterns, **not sufficient directory/ownership/path-race protection to copy unchanged**.

## Recommended file transaction

Use a host-side service with a closed six-name enum and no delete/rename/move method. Bind each snapshot/review to installation, host, runtime, configuration/workspace identity, file name, observed absence or content digest and draft digest. Serialize mutations per installation. Read only regular owner files with no-follow opens, enforce 1 MiB before and after reading, and reject hard-linked targets/shared ownership. Resolve and recheck every managed directory component; do not silently replace unsafe links. A descriptor-relative helper is stronger against directory replacement than strings passed to Node `rename`.

Validate strict UTF-8, preserve BOM, Unicode and exact submitted line endings; do not trim, append a newline, normalize Markdown or parse front matter. A browser textarea normalizes line endings, so original CRLF/mixed-line-ending round trips need explicit handling or a native editor/document model with tested byte-preservation behavior. Upload must retain selected bytes without normalization. Display source text or sanitized local-only rendering; no Markdown image loads, commands or HTML execution.

On commit, revalidate the binding and baseline after review, retain an exclusive 0600 original in a private 0700 directory, fsync the candidate, recheck immediately before replacement, atomically replace, verify persisted bytes and record metadata-only evidence. For a missing target, exclusive creation/link semantics must reject a missing-to-existing race. Do not truncate the original in place. A failed or unknown write must never restart or retry automatically. Ordinary external editors do not honor an advisory lock; a check-then-rename implementation cannot claim universal filesystem compare-and-swap. Document the qualified concurrency boundary and add fault/race hooks so this limitation is not hidden behind a digest check.
