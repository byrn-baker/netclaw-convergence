# VM Security advisory analysis v1

`GET /v1/vm-security?site=...` requires the existing status-reader bearer token. Source IDs/site/node come only from authenticated hypervisor configuration. The public proxy must authorize `req.site` and allowlist this response. No new alerts, cases, enforcement, probes or guest changes.

Top-level: `{status: 'configured'|'not_configured', generated_at: unix_seconds, window_seconds: 300, sources: [Source]}`.

Source: `{id, site, node, status: 'reporting'|'stale'|'unknown', last_contact: unix_seconds|null, observed_at: unix_seconds|null, coverage: Coverage, summary: Summary, findings: [Finding], vms: [VM]}`. Source freshness requires snapshot and last contact at most 60 seconds old. A stale source can retain historical findings inside the trailing five-minute window; never label these ongoing. After the window passes, no findings means insufficient current evidence, never safe/healthy.

Summary: `{finding_count: int, affected_vm_count: int, findings_truncated: bool, assessment: 'review'|'no_patterns_observed'|'insufficient_evidence'}`. Counts cover all calculated patterns; the findings list is capped at 100. `no_patterns_observed` is an observation qualified by coverage, never an all-clear.

Finding: `{id: stable_20_character_hash, kind: 'port_scan'|'network_sweep'|'protected_network_contact', severity: 'review', vm_id: int, vm_uuid: string, first_seen: unix_seconds, last_seen: unix_seconds, evidence: Evidence, caveat: string}`. UI titles should say “Possible port scanning”, “Possible network sweep”, and “Protected network contact”.

Evidence: `{unique_tcp_five_tuples: int, unique_destination_ports: int, unique_destination_ips: int, destination_ip: string|null, destination_port: int|null, examples: [Example]}`. Example: `{src_ip, dst_ip, src_port: int|null, dst_port: int|null, protocol, tap, ifindex: int, observed_at: unix_seconds}`. At most five examples per finding. Counts are exact for the eligible, deduplicated retained sample; they do not estimate missing traffic. TCP five-tuples are deduplicated per VM UUID, across interfaces. Packet counts never become attack counts. Source IPs are observed claims and never establish ownership. UUID plus trusted source and current continuous vNIC identity provides VM attribution; allocation/customer ownership remains unresolved.

VM: `{vm_id: int, vm_uuid: string|null, power_state: 'running'|'stopped'|'unknown', capture_state: 'observing'|'partial'|'unavailable'|'stopped', finding_count: int, nics: [{name, tap, ifindex: int|null, capture_state: 'observing'|'unsupported'|'absent'|'error'}]}`. Includes stopped, unsupported and UUID-missing inventory. Do not present inventory as safety verdicts.

Coverage: `{fresh: bool, sampled: true, inventory_ok: bool, packet_capture_ok: bool, capture_drops_total: int|null, capture_drops_recent_delta: int|null, events_discarded_total: int|null, events_discarded_recent_delta: int|null, counter_delta_seconds: number|null, snapshot_count: int, snapshot_span_seconds: number, max_snapshot_gap_seconds: number|null, history_count: int, history_limited: bool, missing_uuid_vm_count: int, excluded_identity_events: int, metadata_count: int, metadata_cap_reached: bool, policy_configured: bool, allowlisted_tuple_count: int, limitations: [string]}`. Counter totals are collector-session cumulative; recent deltas require two retained snapshots in the same session, and their interval is `counter_delta_seconds`. A null delta means unknown, not zero. Snapshot count/span and maximum inter-snapshot gap describe the available portion of the requested window; a null gap means fewer than two snapshots, not zero. Missing periods are not silently treated as observed. Discards include capacity, parsing and identity loss; they are not firewall blocks. `allowlisted_tuple_count` counts matching retained observation rows before deduplication. `metadata_cap_reached` marks a full latest 256-record snapshot; this and sampling limit completeness independently of kernel drops. `history_limited` conservatively marks a full 10,000-row history window. `excluded_identity_events` counts records excluded for session, identity or timestamp mismatch. The limitations explain other collector exclusions and freshness gaps.

Default signals use guest-egress TCP metadata: at least 20 distinct destination ports to one IP from a VM within 300 seconds, or at least 20 distinct destination IPs at one destination port from a VM. Findings are possible patterns for review, not proof of attack, compromise, delivered packets or successful connections. UDP/ICMP alone never trigger TCP scan findings.

Optional explicit observer configuration:

```json
{"vm_security":{"policies":[{"source_id":"configured-source","node":"configured-node","monitored_vm_ids":[100],"protected_cidrs":["192.0.2.0/24"],"allowlisted_tuples":[{"vm_id":100,"protocol":"tcp","dst_cidr":"192.0.2.10/32","dst_ports":[443]}]}]}}
```

This is documentation-only addressing, not production policy. A policy must bind a configured source/node and is unique per pair. Only monitored VM IDs trigger protected-network contact patterns. Explicit allowlisted VM/protocol/destination-CIDR/port tuples are excluded from every pattern, including scans. TCP/UDP exceptions require explicit ports; ICMP/ICMPv6 require an empty port list. There are no implicit trusted ranges, IP ownership assumptions or management CIDRs. Default configuration enables scan patterns only.

Read-only analysis loads at most 10,000 admitted observation rows per configured source in the requested site over the trailing 300 seconds. New event rows persist collector boot/session provenance; legacy rows without provenance are excluded. Continuous NIC bindings retain their earliest valid timestamp; UUID, TAP, ifindex, absence or session changes reset both the time boundary and a sequence generation; equal timestamps cannot resurrect old identities. Reused interfaces cannot inherit preceding identities' findings. Missing UUIDs are never analyzed. Snapshot history retains bounded counter samples for delta interpretation. All writes happen during existing authenticated snapshot admission and share its transaction; endpoint reads never create cases or mutate collector/configuration state.
