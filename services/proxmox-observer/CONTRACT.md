# Proxmox observer v1 contract

Passive infrastructure evidence, not IDS verdicts. No payload/PCAP retention, guest software, forwarding/firewall mutation or automatic enforcement. All QEMU VMs within the configured collector inventory scope (the entire node by default, or an explicit inclusive --vm-id-range), including stopped VMs; UUID can be null only when config lacks it. No VM names, customer names, allocation/tenant claims. Attribution is node+UUID+vNIC+ifindex at observation time; rental allocation resolution is not yet implemented and must be labeled unresolved.

Node writes atomic root-only JSON snapshot every15s; backend reads it through existing strictly pinned root SSH and publishes via HTTPS (directly or through the fixed pinned management-host publisher) to separate authenticated /v1/hypervisor-events. No new listening socket or credential on hypervisor. Bounded rolling metadata, explicitly sampled; connection history can be incomplete on disconnect and must not be presented as complete forensic capture.

Top-level JSON: schema_version:1, sequence:positive int, observed_at:unix seconds, collector_started_at:unix seconds, node:string, boot_id:UUID string; collection:{inventory_ok:bool, packet_capture_ok:bool, sampled:true, capture_drops:nonnegative int, events_discarded:nonnegative int, limitations:[strings]}; vms:[VM], connections:[connection]. Receiver must authenticate source separately, pin site/node from config and reject body mismatch. Auth config hypervisors:[{id,site,node,token_sha256}]. Existing sensor/guest/status tokens cannot publish hypervisor evidence.

VM: {vm_id:positive int, vm_uuid:UUID string|null, power_state:'running'|'stopped'|'unknown', nics:[NIC]}.
NIC: {name:'netN',tap:'tapVMIDiN',ifindex:positive int|null,mac:string,bridge:string,vlan:int|null,present:bool,rx_bytes:int|null,tx_bytes:int|null,rx_packets:int|null,tx_packets:int|null,capture_state:'observing'|'unsupported'|'absent'|'error',firewall_drop_packets:int|null}. Counters are cumulative kernel-interface counts; guest egress is TAP RX, ingress TAP TX. Firewall counters optional aggregate only, never a per-flow verdict.
Connection: {vm_id,vm_uuid,tap,ifindex,observed_at,direction:'guest_egress',ip_version:4|6,protocol:'tcp'|'udp'|'icmp'|'icmpv6',src_ip,dst_ip,src_port:int|null,dst_port:int|null,packet_count:positive int,evidence:'packet_metadata',verdict:'unknown'}. Only latest bounded metadata, no protocol contents. Unparsable/tunneled/fragmented/extension traffic coverage must be explicit. Connections must match current VM/NIC identities or be discarded as unattributed; IP is an observed claim, not ownership.

Bounds: snapshot512KiB,256 VMs,1024 NICs,256 connections,64 limitations of <=256 characters; no nonfinite numbers, duplicate JSON keys, future>30s, snapshot older>120s; sequence/session replay rejected. Receiver durable separate SQLite within existing state_dir, keeps latest snapshot/node and up to10000 metadata events/node with24h TTL, bounded ingress/history; no automatic cases. Status route GET/v1/hypervisor-status?site=... uses existing status token, includes source configured/freshness (stale after60s), trusted source id/site, latest snapshot; no token or client IDs. API must req.site authorize and allowlist output; UI shows allVMs/capturegaps, never healthy/safe verdict.

An explicit `--vm-id-range 6000:6999` limits inventory, interface counters and capture together. The node publishes only selected VM/NIC identities and labels the scope in collection limitations; the schema remains unchanged. Future selected IDs are discovered automatically.
