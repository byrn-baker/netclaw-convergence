# NetClaw 1.4.0

Coordinated release proposal for specs 135–140. Maintainers should confirm the batch and version before merge; this change does not tag or publish a release.

## Changes

- Opt into a concrete trusted LAN interface for the HUD while keeping the API on loopback. Resolve the configured agent and support browser UUID creation on HTTP LAN origins.
- Select an available model and supported reasoning effort in the bottom Chat composer. Show recorded context usage and provider account quota windows.
- Show Settings from the selected agent's runtime configuration without exposing raw configuration or authentication profiles.
- Restore chats across refresh and reopen previous browser-owned gateway conversations with the original session context. Preserve per-tab drafts, model and effort when switching chats.
- Use a bounded 15-minute gateway chat deadline with a longer frontend proxy deadline and explicit uncertain-outcome errors.

## Upgrade and compatibility

Restart the API and frontend after updating. Loopback remains the default. Set HUD_HOST to a concrete interface IP only for trusted LAN clients; this adds no authentication or TLS. For authenticated remote access, use the documented SSH tunnel.

Model and history features use installed OpenClaw models.list, sessions.patch, sessions.list and chat.history RPCs. The exercised runtime was OpenClaw 2026.9.7 on Ubuntu. Failed discovery falls back to configured model choices; unsupported settings fail before inference. Runtime configuration is not rewritten.

Existing sessionStorage data remains readable. Previous-chat recovery requires the owning browser cookie and retained gateway transcript. Unbound legacy chats and other browsers are not automatically imported. Drafts remain per-tab. Transcript display and browser archives are bounded; partial history and storage failures are reported. Requests are never automatically resent after an uncertain outcome.

Rollback by checking out the preceding release and restarting the HUD. OpenClaw settings are unchanged. Per-chat runtime model/effort selections remain session state; restore agent defaults explicitly if desired. New history metadata is additive and older code ignores it.

## Validation and known limitations

322 HUD unit/API tests and the production build passed. Browser checks cover desktop/mobile layout, model/effort controls, refresh, saved-chat switching and original-session follow-ups using intercepted inference requests. Read-only live gateway history and dedicated non-inference session-setting checks passed. Prior interface verification included a real chat reply; see the detailed evidence.

No current paid inference, fleet operations, macOS/Windows execution or alternate-provider acceptance was performed for this packaging review. Account pricing is not provided, so the effort slider does not rank exact model costs. Trusted LAN access is not a multi-user authentication design. Existing bundle-size warnings remain.
