# NetClaw 1.1.0 — choose your conversation workspace

NetClaw now opens with a straightforward **Chat** conversation by default. A three-way header control lets you choose **Chat**, **Canvas**, or **OpenClaw ↗**.

- **Chat:** chronological questions and answers, multiline composition, visible working/error states, and a confirmed New chat action. Each conversation has its own authenticated gateway binding. Drafts, history and in-flight replies survive navigation within the HUD tab.
- **Canvas:** the existing branching investigation workspace stays available and remains mounted after first use, preserving its draft and session when you switch away.
- **OpenClaw ↗:** opens the native Control UI in a separate tab using the configured gateway port, path and TLS setting. OpenClaw's framing protection and authentication remain intact; no token or conversation is passed through the link.

Gateway fallbacks and empty replies are reported as service issues rather than presented as live assistant evidence. Valid task-bound Jev assessment links remain available in Chat responses. No additional skills or MCP integrations are added: the release inventory remains **233 skills and 173 MCP integrations**.

## Upgrade

Update your clean source checkout to `v1.1.0` after preserving local changes and configuration. Run from the repository root:

```bash
./scripts/upgrade-hud.sh --check
./scripts/upgrade-hud.sh --apply --install-deps
```

Restart the HUD server using your existing launcher so it loads the new runtime navigation metadata and empty-response handling. Reload the browser. This helper does not restart services automatically. No Canvas database migration or gateway configuration change is required.

## Conversation and access boundaries

Standard Chat keeps its transcript in memory in the current tab. Reloading clears that local view; gateway records follow the runtime's retention. New chat clears the local conversation after confirmation and allocates a fresh thread; it does not delete gateway records. The latest 40 messages are sent as context. Canvas and native OpenClaw retain their separate histories; switching does not transfer drafts or send messages.

The native UI link describes a configured location, not a verified live connection. Its own authentication still applies. If the HUD is reached through SSH forwarding, also forward the gateway port shown in the link. Missing/invalid configuration or an explicitly disabled Control UI disables the link. No iframe bypass or gateway token sharing is introduced.

## Validation

HUD tests/build, scoped HTTP tests against a local fake gateway, and synthetic Chrome desktop/mobile-width review cover this change. No live prompt, paid inference or production device operation was used for verification. See [spec130 verification](https://github.com/automateyournetwork/netclaw/blob/v1.1.0/specs/130-chat-interface-switch/verification.md) for exact results and limits. Existing live gateway/provider/per-host/mobile acceptance boundaries still apply.
