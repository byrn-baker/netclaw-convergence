# NetClaw 1.13.0

Spec: [155 — Comms installer](https://github.com/automateyournetwork/netclaw/blob/v1.13.0/specs/155-border-channel-setup/spec.md). VS Code extension: **1.3.0**.

## Changes

The installer now exposes a searchable Comms inventory for OpenClaw and Hermes:
77 documented entries with explicit runtime, host, role and compatibility outcomes.
Select multiple channels, enter private credentials and restrictive access settings,
and retain independent choices across cancellation and reload. WhatsApp, Slack,
Discord and Teams are included; unsupported or incomplete paths stay visible.

Twilio SMS, runtime telephony and NetClaw tools are distinct. Zoom uses the existing
NetClaw meeting integration. Border conversation accounts and Focused/member tools
have separate ownership. Pinned dependency acquisition, native configuration
readback, inert MCP discovery and owned-service recovery retain the existing
installer's review boundaries. Saved configuration, authentication, transport and
delivery are reported separately.

This release also preserves the official Forward MCP integration already merged
on main in [PR #305](https://github.com/automateyournetwork/netclaw/pull/305).

## Upgrade and compatibility

Extension 1.3.0 requires VS Code 1.109+ and source 1.13.0+ for Comms setup. Update
the extension and reload its window. The extension upgrade does not adopt,
re-enroll, upgrade or activate existing runtime installations. New setup uses
separate homes and credentials. Native Windows runtime hosting remains unsupported;
use the documented WSL remote workflow with its qualification limits.

Read [Comms setup](https://github.com/automateyournetwork/netclaw/blob/v1.13.0/docs/COMMS-SETUP.md)
for account preparation, callbacks, permissions and runtime-specific distinctions.
No provider account, pairing, paid operation or operational test is implied by
installation or catalog selection.

## Validation and known limitations

Mac qualification recorded 261 Python passes/seven skips, with four skipped opt-in
checks passed separately; extension checks recorded 143 passes/three skips.
Both fresh runtime engines, four native registry combinations and all four actual
VS Code runtime/setup scenarios passed their documented installer checks. Runtime
and editor fixture neighbors and selected existing-state baselines were preserved.
Positive service fixtures use controlled manager/provider responses; actual engine
reports were inspected separately from the product report/export controls.

**WSL qualification remains partial; the task ledger is 49/50.** Its six extension
service-manager failures and genuine remote-editor acceptance remain open, along
with the recorded fixtures. Provider authentication, transport and delivery remain
unverified for this installer acceptance. These limits are not changed by release.
