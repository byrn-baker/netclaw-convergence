# NetClaw 1.3.0

Spec: [134 — NetClaw as a ChatGPT Dot](../../specs/134-netclaw-dot/spec.md)

## Changes

Adds `mcp-servers/netclaw-dot-mcp`, an operator-run MCP service that lets a ChatGPT Dot use a locally running NetClaw. Five tools: synthetic read-only `netclaw_inventory`, `netclaw_health_summary` and `netclaw_audit_status`; and `netclaw_ask` with `netclaw_job_result`, which hand a request to the local OpenClaw agent as a polled job so long investigations survive a Dot's short tool-call timeout. The agent keeps DefenseClaw, the gateway approval gate and ServiceNow change control; a Dot's approval does not replace them. Includes a single-owner OAuth 2.1 server, an nginx helper (`scripts/dot-nginx-enable.sh`) and the [operator guide](../NETCLAW-DOT.md).

## Upgrade and compatibility

Optional and off by default: the service is not registered as an agent MCP and starts only when an operator creates its secrets file and unit. No existing configuration, federation enrollment or device is changed. Anything returned by `netclaw_ask` is visible to the hosted model, so use lab data only. Exposure requires an operator-owned TLS host; `sudo scripts/dot-nginx-enable.sh` backs up, validates and rolls back its nginx edit.

## Validation and limitations

25 offline tests (`tests/dot`, declared as the `dot` contract suite) pass, and the catalog reconciliation surface passes. Live evidence from a real Dot account is recorded in the [verification record](../../specs/134-netclaw-dot/verification.md): 215 requests from OpenAI's MCP client, 11 completed agent jobs, two jobs that hit a 10-minute ceiling (now 20). Not yet tested: mobile, background and offline behavior, and a revoke-and-confirm test. Live (non-synthetic) health tools remain refused by design. Experimental; source release only.
