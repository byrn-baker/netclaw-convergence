# NetClaw 1.16.0

Spec: [1012-convergence-home-onboarding](../../specs/1012-convergence-home-onboarding/spec.md)

## Changes

Adds optional Linux Docker flow onboarding for one ordinary computer: a generated
traffic demonstration or explicit local-interface capture with softflowd. Neither
requires Cisco equipment, Proxmox, Kubernetes, router credentials or a model login.
Retained records pass through GoFlow2, OTel and VictoriaLogs into the existing API,
MCP tools and HUD. Coverage labels distinguish synthetic, host-only and configured
network exporters. The default core installation remains unchanged.

Private flow bundles bind their containers, retained volumes and network to a
persisted identity; conflicting bundle/mode/site ownership is rejected before
starting services or sending demo data. Collection is loopback-only, host capture
is explicit, and raw buffering and archive retention are bounded.

Includes upstream's merged specification-only proposal #309 and its accessible
onboarding follow-up requirements. No clean upstream runtime integration is claimed.
The existing avatar test now waits for observable React transitions instead of a
fixed sleep; all assertions and avatar runtime behavior are preserved.

## Upgrade and compatibility

Existing core Docker and K3s bundles keep their behavior. Create a fresh private
bundle/project for either flow mode; use separate projects/sites for demo and host
observations. Retain the bundle and its identity with the data; recreating it or
moving it to another path does not silently adopt old resources. No automatic
service restart, data migration, tag or release publication is performed.

## Validation and known limitations

See the [verification record](../../specs/1012-convergence-home-onboarding/verification.md)
and [installation matrix](../convergence/verification.md) for executed results.
Real packet capture qualification uses only a filtered localhost HTTP fixture;
physical adapters, whole-LAN visibility, IDS, macOS and Windows remain separate.
The actual API/MCP/HUD component checks and isolated Chromium rendering do not
qualify a full gateway/session/model investigation. Resource snapshots from a small
fixture are not minimum requirements or throughput guarantees.
