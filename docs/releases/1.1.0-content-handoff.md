## New angle

**A familiar chat by default, with room for deeper investigations.**

NetClaw 1.1.0 adds a standard back-and-forth chat as the HUD's default view. The header offers three choices: Chat, Canvas, and the native OpenClaw interface in a separate tab. People can begin with an ordinary conversation and choose Canvas when they want a branching investigation workspace.

The new Chat uses the existing authenticated gateway with an isolated conversation identity. Navigating between HUD views preserves the current draft and in-flight reply. Canvas stays available and preserves its existing session behavior. Native OpenClaw retains its own authentication and history; the link carries no credentials.

## Facts and boundaries

- Inventory is unchanged: **233 skills / 173 MCP integrations**. The UI adds no new integration.
- This is a minor feature release, **1.1.0**, following the first official **1.0.0** source release.
- Chat history is retained in memory in the current HUD tab; reload clears that local view. Gateway records follow runtime retention. Do not claim cross-device sync, durable Chat archives or shared histories across the three interfaces.
- Chat sends the latest 40 messages as context. New chat creates a fresh thread after confirmation; no deletion of gateway records.
- The native interface opens separately because OpenClaw blocks framing. It is not embedded, automatically logged in, or made public. Remote users also need the gateway port forwarded.
- Failed/empty/unconfirmed gateway responses are service errors, not invented assistant findings. Existing approvals and operational authority remain unchanged.
- Validation uses offline tests, a fake local gateway and synthetic browser review. Do not claim a live production investigation was demonstrated.
