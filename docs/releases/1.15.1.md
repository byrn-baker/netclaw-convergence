# NetClaw 1.15.1

Spec: [1011-convergence-readiness](https://github.com/byrn-baker/netclaw-convergence/blob/v1.15.1/specs/1011-convergence-readiness/spec.md).
Source metadata for the Convergence fork; this is not an upstream release announcement.

## Changes

Repairs inherited CI gaps: missing historical spec artifacts, owned FastMCP dependency
contracts, an incomplete startup-test fixture and the SQLite metrics test dependency.
New runtime homes are created privately even with a group-writable shell umask.
Existing runtime permissions and operator content remain unchanged.

Adds a disposable VictoriaLogs-to-API-to-HUD flow-evidence integration check to
native Linux Docker CI. It verifies persisted records after restart, site/exporter
isolation, production proxy/rendering behavior, same-window evidence and outage
reporting. The upstream proposal is narrowed separately to one optional read-only
flow-evidence integration; no upstream implementation is shipped here.

## Upgrade and compatibility

No live deployment or database migration is required. Optional fork MCP servers
now declare the repository-tested FastMCP 4.0.11 / MCP 2.3.0 versions; rebuild their
isolated environment when upgrading those servers. Prisma's standalone Dockerfile
now installs the same requirements manifest. Production integrations were not
reinstalled or reconfigured during verification.

## Validation and limits

See the [verification record](https://github.com/byrn-baker/netclaw-convergence/blob/v1.15.1/specs/1011-convergence-readiness/verification.md)
for exact commands and outcomes. Historical artifacts are labeled retrospective;
their presence does not prove original planning order or operational acceptance.
The flow test uses actual storage/HTTP routes and JSDOM rendering, not a full
browser/gateway/model investigation. Actual macOS Docker Desktop and Windows/WSL2
qualification remains pending a test host; the operator plans a dedicated WSL VM.
No tag or published release is implied by these metadata files.
