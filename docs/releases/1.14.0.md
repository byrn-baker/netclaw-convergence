# NetClaw 1.14.0

Spec: [160-dynamic-pyats-testbeds](https://github.com/automateyournetwork/netclaw/blob/v1.14.0/specs/160-dynamic-pyats-testbeds/spec.md)

## Changes

Static or dynamic pyATS testbeds can now be selected per claw in the VS Code
installer (extension 1.4.0), terminal plan builder and `scripts/setup.sh`.
Fourteen source routes cover Itential, NetBox, Nautobot, Catalyst Center, CML,
containerlab, EVE-NG, GNS3, ServiceNow, OpsMill Infrahub, IP Fabric, Forward,
structured records and reviewed REST exports.

The pinned upstream pyATS MCP includes eight dynamic tools. NetClaw adds managed
composition, explicit management endpoint/OS mapping, freshness and completeness
checks, credential references, immutable candidates and validation-gated activation.
Existing source MCP tools provide inventory; unsupported reader gaps are explicit.
See the [operator guide](https://github.com/automateyournetwork/netclaw/blob/v1.14.0/docs/DYNAMIC-TESTBEDS.md).

## Upgrade and compatibility

Existing plans and runtime environments default to static mode. Existing homes,
credentials and testbed files are preserved. Updating source or the extension does
not upgrade an installed runtime. Reinstalling the selected pyATS component is an
explicit operator action. The new wrapper needs the new pinned upstream runtime;
use matching source 1.14.0 and extension 1.4.0 for dynamic setup.

Dynamic candidates live in one MCP process. Use a persistent native client for
device operations. Restart requires rebuilding and revalidating; there is no static
fallback in dynamic mode. The bounded CLI helper only previews/validates and,
optionally, activates/lists within its own process; that process then ends.
Each managed process now owns a private task database/artifact directory. Old
SQLite evidence remains on disk, but a restarted bridge does not reconnect old
task handles; investigate interrupted outcomes before any replay.
Raw native source fetches, arbitrary REST/file inputs, static merges and implicit
activation are blocked by the managed boundary. They are not qualified source routes.
The HUD/editor's static testbed, collector grants and Terminal Intent are separate.

## Validation and known limitations

[Spec160 verification](https://github.com/automateyournetwork/netclaw/blob/v1.14.0/specs/160-dynamic-pyats-testbeds/verification.md)
records the actual isolated runtime, source fixtures, installer, UI and regression
checks. Schema validation is not a reachability, login or command-execution result.
Live tenant/lab qualification across all source products and Windows/WSL acceptance
are not claimed. Native Mac selection/save/reload acceptance passed in VS Code
1.145 Insiders; stable/minimum-editor visual qualification remains open.

The coordinated VS Code extension is **1.4.0**. Installing it does not upgrade an
existing NetClaw runtime. Read the [community announcement](https://github.com/automateyournetwork/netclaw/blob/v1.14.0/docs/blog/2026-10-30-dynamic-pyats-testbeds.md).
