# NetClaw 1.2.1

Spec: [133-installer-python-isolation](https://github.com/automateyournetwork/netclaw/blob/v1.2.1/specs/133-installer-python-isolation/spec.md)

## Changes

The installer creates isolated runtimes for legacy Python components and configures MCP launch commands to use the installed interpreter or console entry point. Protected system Python remains untouched. Dependency failures survive warning handlers and subshells and make the install fail visibly. Only successful, artifact-verified selections receive new registrations.

BGP Intelligence and four other components no longer depend on Claw Certification initializing their repository path. Nautobot installs the bundled server used by its registration. gNMI starts with the supported FastMCP constructor argument.

The larger install selection also revealed UML SDK constraints, Memory MCP wheel packaging and a changed MemPalace module layout. These are corrected, with local tool discovery verified.

## Upgrade and compatibility

Rerun the installer with the desired components. Keep existing runtimes until verification passes. OpenClaw registration preserves unrelated settings and credentials, retains private backups, and refuses to overwrite custom launch commands. Existing Hermes MCP blocks retain the sidecar merge workflow. See [Python runtime migration](https://github.com/automateyournetwork/netclaw/blob/v1.2.1/docs/PYTHON-RUNTIME-MIGRATION.md).

## Validation and known limitations

Installer regressions, the broader unit suite, reconciliation and fresh-runtime MCP discovery passed. Fresh discovery covered BGP, gNMI, Nautobot, SuzieQ and Firewall Rule Analyzer. Credentialed endpoint calls and device operations were not tested. Optional source checkouts remain prerequisites for their respective components. See [verification](https://github.com/automateyournetwork/netclaw/blob/v1.2.1/specs/133-installer-python-isolation/verification.md).
