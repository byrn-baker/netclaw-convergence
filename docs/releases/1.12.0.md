# NetClaw 1.12.0

Spec: [153 — IDE installer](https://github.com/automateyournetwork/netclaw/blob/v1.12.0/specs/153-ide-installer/spec.md).

## Changes

Set up a new NetClaw from VS Code without an existing runtime or HUD connection.
Choose one Focused claw or a mixed OpenClaw/Hermes Risk, give each claw a new empty
home and independent credentials, then review the exact installation plan natively.
The wizard, CLI and assistant drafting tools share one catalog and setup engine.

Setup records verified checkpoints, pauses on uncertain outcomes, requires explicit
resume, exports structurally redacted reports and removes only verified owned
artifacts during separately reviewed cleanup. Save a VS Code connection after
authenticated runtime/HUD readiness succeeds. Deployment Spec Kit and assistant
tools help draft plans; they cannot bypass native approval or retrieve secrets.

WSL return fixes cover literal systemd environment/working-directory paths,
boot-aware process identity, managed companion Python, collected-unit detection
and clearing a previous run from the wizard when accepting a new plan.

## Upgrade and compatibility

Source 1.12.0 and Marketplace extension 1.2.0 are separately versioned. Extension
1.2.0 requires VS Code 1.109 or later. New setup selects source 1.12.0 or another
explicitly reviewed compatible source; older checkouts without the setup protocol
cannot run it. Read the [setup guide](https://github.com/automateyournetwork/netclaw/blob/v1.12.0/docs/GETTING-STARTED-VSCODE.md).

Existing claws remain separate connections. Updating the extension or source does
not upgrade, adopt, re-enroll or restart an existing runtime. Native Windows runtime
hosting is unsupported; use the intended WSL distribution and its extension host.
Production setup remains gated on actual installation-bound control evidence;
testing mode requires an explicit choice and review. No provider credentials or
private runtime state are distributed.

## Validation and known limitations

The [Mac return acceptance](https://github.com/automateyournetwork/netclaw/blob/v1.12.0/specs/153-ide-installer/mac-return-installer-acceptance.md)
records three additional actual native VS Code scenarios: fresh OpenClaw, fresh
Hermes with cancellation/checkpoint resume, and a fresh four-claw mixed Risk.
All six installations passed required Tiers 1–3, with authenticated connection
handoff and verified owned cleanup. These used fresh homes on an existing Mac;
earlier clean-OS bootstrap evidence is separate. No model sessions, device calls
or channel messages ran in this installer acceptance.

Mac regression passed 136 extension tests, 138 setup cases and 216 installer cases
plus 16 subtests, with explicit platform/optional skips. WSL recorded all 140 setup
tests passing on Ubuntu 24.04 and 26.04, plus partial actual-host acceptance.
Ubuntu 26.04 focused installers and mixed Risk passed; Ubuntu 24.04 Hermes setup
remained interrupted/unknown. Some actual WSL/client/cold-wake and native Windows
gate scenarios remain unrun. Those results are not promoted to passes by this
release. See [release verification](https://github.com/automateyournetwork/netclaw/blob/v1.12.0/specs/153-ide-installer/release-verification.md)
and the [WSL matrix](https://github.com/automateyournetwork/netclaw/blob/v1.12.0/spec153-wsl-return/matrix.json).
