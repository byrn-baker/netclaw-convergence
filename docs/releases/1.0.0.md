# NetClaw 1.0.0 — the network engineering workspace

NetClaw's first official versioned source release brings together **233 skills and 173 MCP integrations**, a new function-first HUD, the preserved Canvas investigation workspace, specialist federation, document-grounded retrieval and optional Jev advisory assessments.

## Highlights

- **New operations HUD:** Basic/Advanced views, Claw/MCP and reported-model drill-downs, RAG uploads and cited retrieval, Tokenomics, service Logs, masked Configuration, Security panels and searchable Documentation/CLI/API references. Optional Three.js views complement the tables.
- **Canvas preserved:** Adam Mason's branching context/chat workspace remains available, with its session library, attachments and investigation tools. Selected evidence can be handed to a Canvas draft. Previous controls remain at `/classic.html`.
- **A risk of NetClaws:** run standalone or coordinate scoped specialist members through a Border, with separate external-neighbour and mobile-edge views.
- **Optional Jev Science Officer:** dynamically composed advisory questions, typed assessments, visible influence and task-bound detail, with configurable budgets and private-data disclosure controls. Advice does not grant execution authority.
- **Knowledge and evidence:** local document retrieval with citations, layered memory, source-aware network analysis and GCF compact evidence serialization.
- **Multiple ways to work:** chat, HUD, mobile source clients and Zoom meeting integration, subject to the services and credentials you configure.
- **Operational discipline:** observation before changes, recorded baselines, ITSM approval gates, verification and GAIT audit trails remain central to network operations.
- **A contribution and release foundation:** numbered specs and Spec Kit for every PR, a PR checklist, isolated contract suites, versioned release notes and a repeatable `1.x.y` release process.

The inventory includes optional and externally installed integrations; it is not a claim that every provider is configured, connected or tested in your environment.

## Install and upgrade

This release distributes repository source. GitHub supplies the source archives; no desktop/mobile binary or container image is attached.

```bash
git clone --branch v1.0.0 https://github.com/automateyournetwork/netclaw.git
cd netclaw
./scripts/install.sh
```

Run the installer as your normal user. Choose the components and runtime appropriate to your environment, then follow the [README](https://github.com/automateyournetwork/netclaw/blob/v1.0.0/README.md) for credentials and onboarding.

For an existing checkout, preserve local changes and configuration, fetch tags, and select `v1.0.0`. To check and rebuild the HUD from that checkout:

```bash
./scripts/upgrade-hud.sh --check
./scripts/upgrade-hud.sh --apply --install-deps
```

The helper installs lockfile dependencies when requested and rebuilds the HUD; it does not upgrade every integration, restart your services or migrate runtime configuration. Follow component-specific instructions for other changes. Existing Canvas browser storage is preserved by the HUD implementation.

## Validation boundaries

Offline contracts, reconciliation and HUD tests/build are release checks. Live gateway binding, RAG ingestion, provider connections, per-host behavior and real phone/watch/browser journeys still require acceptance on the operator's deployment. Detailed evidence and remaining gaps are in [HUD verification](https://github.com/automateyournetwork/netclaw/blob/v1.0.0/specs/127-function-first-hud/verification.md) and [release verification](https://github.com/automateyournetwork/netclaw/blob/v1.0.0/specs/129-release-1-0/verification.md). This release does not declare the broader flagship audit complete.

Mobile app-store distribution has its own lifecycle and version numbers; publishing this repository release does not announce Apple or Google approval. Optional integrations and paid model providers require their own setup. The HUD remains a local operations service with existing access controls.

## Contribute

Start with a numbered specification, use Spec Kit to carry it through planning and tasks, and link the artifacts and verification in your PR. Read [CONTRIBUTING.md](https://github.com/automateyournetwork/netclaw/blob/v1.0.0/CONTRIBUTING.md).

Future completed feature specs advance the minor version (`1.1.0`, `1.2.0`); fixes, documentation and maintenance advance the patch (`1.0.1`, `1.1.1`). Spec identifiers remain independent of version numbers. See the [release process](https://github.com/automateyournetwork/netclaw/blob/v1.0.0/docs/RELEASING.md).
