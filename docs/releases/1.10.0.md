# NetClaw 1.10.0 — source metadata, publication held

## Changes

- Redesign the VS Code extension with theme-aware cards, clearer headings/forms and connection guidance, bundled artwork and an attributable Three.js BGP view. Preserve blue primary actions, search and filters.
- Add reviewed testbed CRUD and advanced YAML, with YAML/JSON/CSV import/export, credential masking, stale-edit protection and private recovery copies.
- Add contextual per-MCP environment fields and reviewed supported install/register/restart actions using existing scoped helpers.
- Expose native-bound DefenseClaw tool rules/enforcement defaults and OpenShell sandbox network policies, with status/log snapshots, before/after review, explicit weakening acknowledgment and verified or unknown outcomes.

## Upgrade and compatibility

These are unpublished source changes. The owner authorized committing, pushing and merging Spec151, but has not authorized a release tag, GitHub release, VSIX packaging, Marketplace publication or runtime deployment. Repository source version1.10.0 does not change the extension's0.1.0 component version or the existing Spec150 VSIX.

The new testbed/configuration editors require the corresponding source HUD routes; older HUDs show unavailable guidance without falling back to legacy raw writes. Existing configuration and installation bindings remain compatible. Review helper commands and shared security scope explicitly before use. No service is installed, restarted or security policy changed simply by opening a view or merging source.

Private recovery material is retained for explicit inspection. Do not blindly replay interrupted setup/security changes or restore an old policy over another operator's work. OpenShell has no atomic revision precondition: the extension rechecks before applying, serializes its own shared-target operations and verifies readback, but external writers can race. Global effective OpenShell policies remain read-only.
